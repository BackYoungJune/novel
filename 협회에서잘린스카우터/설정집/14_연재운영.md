# 매일 연재 운영 규칙 (확정)

2026-10-28 작가 지시: 매일 먼저 문피아 한 화 업로드를 준비하고, 그다음 신규 회차를 집필·검증·커밋·푸시한다. 게시 전 검토와 독자 댓글 반영을 기본 절차에 넣는다. 시간은 모두 한국 시간이다.

## 04:00 게시 준비와 08:00 공개 예약

1. 문피아 작품 관리에서 실제 공개·예약 회차와 시각을 확인한다. 이미 예약된 회차가 있으면 다시 올리지 않는다. 공개된 마지막 회차의 바로 다음 **한 화**를 고른다. 2026-11-01 확인 기준 001~008화가 공개돼 있으므로 다음 대상은 009화다. 매일 실행 시에는 이 기록보다 실제 관리 화면의 최신 상태를 우선한다.
1-1. **2026-11-01 작가 지시 — 진행 개작 게시 조건:** 다음 회차의 [1~66화 진행 점검](../기록/1-66화_진행점검_2026-11-01.md) 항목에 `개작 완료`가 명시되고, 해당 `원고/NNN.md`와 `게시/NNN.txt`의 개작·검증 커밋이 `origin/main`에 있어야 예약할 수 있다. 국소 오탈자 수정이나 게시 직전 점검만으로 개작 완료로 간주하지 않는다. 조건이 없으면 그 회차의 예약을 보류하고 이전 공개분 댓글 확인을 계속한다. 2026-11-01 현재 009화는 개작 완료 표시가 없어 예약 대상이 아니다.
2. 해당 `원고/NNN.md`의 최신 변경 내역·작가 결정·앞뒤 회차·설정·연속성 대장을 읽는다. `게시/NNN.txt`가 원고의 최신본과 일치하는지 확인하고, 다르면 게시본을 다시 만든다. 제목, 본문 누락·중복, 회차 순서, 시점·시간선·인물 지식, 오탈자와 문장 호흡, 분량을 점검한다. 숫자 검사와 실제 독해를 모두 수행한다.
3. 이전 공개분 댓글을 확인해 아래 기준에 따라 필요한 수정을 먼저 반영한다. 게시 직전 본문과 원고·게시본을 다시 대조한다.
4. 검토가 통과하면 문피아에 **같은 날 08:00 예약 공개**로 등록하고, 관리 화면의 회차·제목·예약 시각·상태를 확인한다. 예약 기능이나 로그인에 문제가 있으면 임의로 즉시 공개하지 않는다. 상태를 기록하고 작가에게 알린다.
5. 08:00 이후 공개 여부는 확인 가능한 실행 시점에 실제 목록에서 확인한다. 예약 상태만 확인한 경우 공개 완료로 기록하지 않는다. 당일 예약이 불가능하거나 검토가 끝나지 않으면 무리해서 게시하지 않는다.

## 댓글 반응 확인과 수정

- 공개된 회차의 새 댓글을 매일 읽고, 회차·확인 날짜·핵심 지적·근거·처리 결과를 `게시/연재운영_대장.md`에 기록한다. 댓글 하나만으로 취향을 단정하지 않고 반복 여부와 원고의 실제 장면을 대조한다. 독자의 개인정보는 기록하지 않는다.
- 설정·연속성 오류, 오탈자, 의미를 바꾸지 않는 문장 문제는 해당 원고와 게시본을 수정하고 검증한다. 이미 공개된 회차를 고쳤다면 문피아 공개본에도 같은 수정을 반영하고 화면에서 확인한다.
- 이해가 어렵다는 반응, 전개 속도, 인물 매력, 재미·보상감은 원인을 분석해 앞으로의 **미공개** 회차에 적용할 수 있는 구체적 수정안을 만든다. 확정된 설정과 작가 결정 범위 안의 국소 퇴고는 반영한다. 사건·인물 관계·능력·장기 구성 등 기획 선택이 필요한 변경은 제안하고 작가 결정을 기다린다.
- 댓글 수나 조회 수만을 이유로 설명을 덧붙이거나 전개를 뒤집지 않는다. 반영한 변경의 근거와 교차 검토 여부를 기록한다.

## 그날의 다음 집필

- **2026-11-01 작가 지시:** 새 집필 방향을 정하고 001화부터 개작하기로 했다. 그때까지 서버의 067화 이후 신규 집필과 원고 개작을 멈춘다. 서버는 문피아 게시 전 점검·예약·댓글 확인만 계속하고, 게시 대상의 막는 오류에 한한 국소 수정만 한다. 066 초고의 새 전개는 작가 확인 전 초안이다.
- 집필을 재개할 때에도 해당 회차 전개에 대한 작가 승인 또는 명시적 위임을 먼저 확인한다. 구성안 초안이나 미승인 원고만으로 승인된 것으로 간주하지 않는다.
- 작가가 새 집필 방향과 재개를 지시한 뒤에는 `novel-write` 절차로 집필하고 `novel-review` 절차로 분량·문장·설정·연속성을 검증한다. 작성자와 다른 모델·세션의 교차 검토 원칙을 따른다. 집필 후 게시본·연속성 대장·집필 검증 기록을 갱신한다.
- 검증된 작업을 규정된 형식으로 `main`에 커밋하고 `origin/main`에 푸시한다. 게시 예약·실제 공개 확인·댓글 수정·신규 집필을 각각 실제 완료한 범위대로 보고한다.

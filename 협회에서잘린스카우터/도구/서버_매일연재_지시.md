# 서버 매일 연재 작업 지시 (초안)

2026-10-31 작가 지시로 Lightsail 서버에서 매일 실행한다. 범위는 2026-10-28 작가가 정한 매일 연재 운영(CLAUDE.md "매일 연재 운영", [14_연재운영](../설정집/14_연재운영.md))과 같다. 이 지시는 `도구/서버_매일연재.sh`가 `claude -p`에 넘긴다.

오늘 한국 시간 날짜를 먼저 확인하고, 아래 순서로 진행한다. 작업 디렉터리는 저장소 루트(`~/novel`)다.

1. CLAUDE.md, AGENTS.md, `협회에서잘린스카우터/설정집/14_연재운영.md`, `협회에서잘린스카우터/게시/연재운영_대장.md`를 읽고 `git status`와 최근 커밋을 확인한다.
2. 문피아 작품 관리 화면(`https://library.munpia.com/qordud2/novel/detail?novelId=617128&menu=chapter`)을 `munpia-browser` 도구로 열어 실제 공개·예약 회차와 시각을 확인한다.
   - 로그인이 풀려 있으면 로그인하지 않는다. 비밀번호를 입력하지 않는다. 게시를 보류하고 이유를 기록한다.
   - 이미 예약된 회차가 있으면 다시 올리지 않는다.
3. 공개된 마지막 회차의 다음 한 화를 정하되, 먼저 [1~66화 진행 점검](../기록/1-66화_진행점검_2026-11-01.md)의 해당 항목에 **`개작 완료`**가 있는지 확인한다. 그 회차의 `원고/NNN.md`와 `게시/NNN.txt`를 바꾼 개작·검증 커밋이 `origin/main`에 실제로 있는지도 `git log`로 확인한다. 두 조건 중 하나라도 없으면 **예약·즉시 공개·게시 화면 입력을 모두 보류한다.** 국소 오탈자 수정이나 이 실행의 게시 전 점검으로 조건을 대신할 수 없다. 이 경우에도 5번 댓글 검토와 사실 기록은 진행한다.
4. 두 게시 조건이 확인된 회차만 14_연재운영의 게시 전 검토대로 점검한다. 최신 원고·게시본·앞뒤 회차·설정·연속성·문장·분량을 대조한다. 분량은 `pwsh -NoProfile -File ./task-start.ps1 -Mode review -Chapters N`으로 잰다. 막는 오류는 국소 수정하고 재검증한다. 통과하면 문피아에 **당일 08:00 예약 공개**로 등록한다. 제목은 `게시/회차목록.md`의 '제목만' 칸, 본문은 `게시/NNN.txt` 전체다. 저장 전에 편집 칸의 본문이 게시본과 같은지 확인한다. 문피아 편집기는 `…`를 `···`로 바꾸므로 같은 변환을 적용해 비교한다. 등록 뒤 관리 화면에서 회차·제목·예약 시각·상태를 확인한다. 예약이 안 되면 즉시 공개하지 않고 보류한다.
5. 이전 공개분 댓글을 확인한다. 근거가 분명한 오류와 표현은 원고·게시본을 고치고, 필요하면 공개본도 수정한다. 전개 변경이나 확정 설정 변경은 하지 않고 선택지만 기록한다.
6. **신규 회차는 집필하지 않는다.** 2026-11-01 작가가 전 회차가 서류·협상 문답 위주로 진행이 약하다고 지적해, 새 집필 방향을 정할 때까지 마지막 보유 원고 이후 집필을 멈췄다. 2026-11-03 첫 통합으로 기존 066은 현재 065가 됐다([번호 대조표](../구성/회차번호_대조_2026-11-03.md)). 원고 개작도 서버에서는 하지 않는다. 게시 대상 회차의 막는 오류 국소 수정만 허용한다.
7. `연재운영_대장.md`와 작품 README에 예약·실제 공개 확인을 구분해 사실대로 기록한다.
8. 수행한 변경만 CLAUDE.md 커밋 규칙대로 `main`에 커밋하고 `origin main`으로 푸시한다. 다른 사람이 만든 미커밋 변경은 커밋하지 않는다.

하지 않는 것: 네이버 게시, 즉시 공개, 중복 게시, 문피아 로그인, 기획 결정 확정, 폐기안 재사용, 저장소 밖 파일 수정, AutoTrader(`/opt/autotrader`)나 서버 설정 변경.

마지막 응답은 완료·보류·미완료를 구분한 5줄 이내 요약으로 끝낸다. 이 요약은 서버 로그에 남는다.

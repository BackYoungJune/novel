# 원고 검증 (확정)

2026-09-30 사용자 요청으로 도입. 점검과 수정을 구분한다. 사용자가 수정까지 요청했거나 novel-write의 자체 검증이면 허용된 오류를 고친다. 점검만 요청이면 근거와 수정안을 보고한다.

## 최신본과 근거
- [인덱스](../INDEX.md)와 [공통 작업 지침](../working-rules.md)에서 기존 규칙의 원본 경로를 확인한다.
- 준비가 안 됐으면 ../task-start/SKILL.md의 1~4단계만 수행한다.
- Claude 등 다른 작업자가 고친 뒤에는 현재 파일과 diff를 읽는다. 예전 문제를 현재 문제처럼 반복하지 않는다.
- 설정집·구성안과 앞뒤 원고를 대조한다. 연속성 대장(`기록/연속성_대장.md`)으로 날짜, 감정 사용 횟수, 인물별 지식, 돈·부상을 빠르게 대조하되, 대장이 원고와 다르면 원고가 기준이다. 취향 제안과 확정 규칙 위반을 구분한다.

## 순서
1. **설정과 시간:** AGENTS의 위반 10항목, 나이·경력·연도, 장면 사이 이동·시간, 하루별 능력 사용과 후유증, 능력 공개 단계, 계약·금액·부상·소지품을 확인한다. 성공과 실패한 감정을 구분하고 설정에 있는 과사용 예외도 읽는다.
2. **시점과 인과:** 주인공이 정보를 얻은 장면이 있는지, 그 판단과 행동이 가능한지, 상대가 믿거나 거부하는 근거가 있는지 본다. 등장인물의 추측을 설정 확정으로 오인하지 않는다.
3. **흡입력:** 도입의 사건, 목표와 방해, 행동으로 달라진 상황, 회차 안의 작은 보상, 다음 화로 이어지는 질문을 본다. 설명 반복·손쉬운 해결·예고만 있는 결말은 해당 대목을 짚는다.
4. **문장:** 09_문장.md의 체크리스트를 순서대로 적용한다. “다.”의 비율만으로 불합격시키지 않는다. 문장 길이·구조·동사 반복, 억지 체언 종결, 지나친 생략, 숫자의 기준, 대사 말투, 시제, 감정 이름과 설명 중복을 실제 문맥으로 읽는다.
5. **기계 검사:** 저장소 루트에서 ./task-start.ps1 -Mode review -Chapters 1,2,3처럼 실제 대상 번호로 실행한다. 본문 분량 결과와 “나는” 후보를 확인한다. “코피 나는” 등 동사 용례는 대명사 횟수에서 제외한다. 스크립트 통과는 분량 확인일 뿐 문학적 완성도나 설정 검증 통과가 아니다.
6. **수정 후:** 바뀐 파일의 분량을 재측정하고 영향을 받는 전후 장면을 읽는다. 모바일 줄 수는 화면 너비에 따라 달라지므로 파일 줄 수만으로 검증 완료라 하지 않는다.

## 교차 검토
작가가 본문을 고치지 않으므로, 초고를 쓴 쪽의 자체 검증만으로는 같은 버릇을 걸러내지 못한다. 작성자와 다른 쪽이 한 번 더 읽는다.

- **누가**: 초고를 쓴 모델·세션과 다른 모델 또는 새 세션. 이 저장소는 Codex와 Claude를 함께 쓰므로 한쪽이 쓰면 다른 쪽이 검토하는 것을 기본으로 한다.
- **어떻게**: 검토자는 작성 대화를 보지 않고 파일, diff, 설정집, 연속성 대장만으로 판단한다. 호출은 "점검만" 요청과 같다.
- **검토자는 수정하지 않는다**: 근거와 수정안만 보고한다. 수정은 집필 쪽이 한다. 두 AI가 같은 파일을 번갈아 고쳐 서로의 수정을 되돌리는 일을 막기 위해서다.
- **언제 필수인가**: 새 회차 초고 직후, 15화 비축을 마친 시점, 연재 시작 직전 1~15화 일괄. 문장 몇 개를 고친 수준은 자체 검증만 해도 되지만 커밋에 그렇게 적는다.
- **같은 모델뿐일 때**: 새 세션에서 점검만 모드로 읽는다. 이 경우 독립성이 낮다는 점을 보고에 적는다.
- **AI 티 점검**: 어미 반복, 문장 길이가 균일한 구간, 같은 구조의 장면 전환, 감정 설명의 중복, 대사마다 같은 말투를 특히 본다. 기준은 09_문장 체크리스트다.
- **커밋에 남기기**: `검증:` 줄에 `교차 검토: 작성 모델 / 검토 모델` 또는 `교차 검토 없음 (자체 검증만)`을 적는다.

## 보고
- 교차 검토였는지, 같은 모델의 새 세션이었는지, 자체 검증뿐이었는지 먼저 밝힌다.
- 회차별 본문 글자 수와 검증 범위를 제시한다.
- 실제 문제만 심각도 순으로 파일·줄 위치, 짧은 인용, 근거 규칙, 독자에게 생기는 문제, 수정 방향을 붙여 보고한다.
- 해결한 문제와 결정이 필요한 문제를 구분한다. 문제를 못 찾았으면 그렇게 말하고 확인하지 못한 범위만 밝힌다.
- 변경이 있으면 AI 작업 범위를 정확히 남긴다. 스킬 호출만으로 커밋·푸시·게시하지 않는다.
